# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Spoken is a Windower4 addon for Final Fantasy XI that reads NPC dialogue aloud with generated voices, inspired by the WoW addon of the same name (https://github.com/rusty-key/spoken-wow). It is a work in progress and not usable yet; `README.md` says so and must keep saying so until there is a release.

Direction (2026-11-15): players use pre-rendered audio packs only; a line without downloaded audio is silent. Everything in `helper/` and `tools/` is the developer-side generation pipeline. Playback is the native Lua C module in `native/` (built 2026-11-16, `libs/spokenplay.dll`); the helper is the developer's live path behind `//spoken mode helper`. `docs/Audio-Packs.md` is the pack design (directories own files; no content-addressed store; lookup by speaker plus cleaned text) and the player's design, `docs/Event-Decoding-Handoff.md` the extraction plan and critical path, `docs/Voice-Handoff.md` the original design record, `docs/Protocol.md` the helper-mode file contract. Do not propose `windower.play_sound` for playback.

It is a sibling of `../Balloon` (the on-screen dialogue balloon) and shares its scaffolding. Keep the Makefile, `.luacheckrc`, and test harness in step with `../Balloon`, `../ahbuddy`, and `../randommount`.

## Install

Windower runs under the Lumoria flatpak at `~/.var/app/net.windower.Lumoria/data/prefixes/prefix-1/pfx/drive_c/Windower4/`. This repo is symlinked into its `addons/` folder so edits are live after a reload:

```
make install        # find Windower and symlink this repo
make where          # print the folder it would use
```

In game: `//lua load spoken` the first time, `//lua reload spoken` after editing.

## Lint and tests

```
make check                     # luacheck, the Lua tests, and the Python tests
luajit test/test_Spoken.lua    # Lua tests alone; Windower is stubbed
python3 -I -m unittest discover -s helper -p 'test_*.py'
python3 -I -m unittest discover -s tools -p 'test_*.py'
make deps                      # cross-build libogg/libopus/opusfile (static, 32-bit) into native/deps/
make native                    # libs/spokenplay.dll; //lua unload spoken before replacing it
make native-test FILE=...      # play one Opus file through the module under the game's Wine prefix
```

Windower's Lua accepts `"fmt":format(x)`; luacheck and luajit do not, so write `("fmt"):format(x)`. `.luacheckrc` whitelists the luau globals; add to it rather than using inline `-- luacheck:` comments.

The Lua harness stubs `luau`, `config`, `chat.chars`, and `windower` (including `get_dir`, `dir_exists`, `file_exists`, and the `ffxi` position calls over an in-memory tree holding two small packs), preloads a fake `spokenplay` that records its calls, then `dofile`s `Spoken.lua` and drives the `incoming text`, `incoming chunk`, `addon command`, `prerender`, and `unload` handlers. File reads and writes go through `io.open`, which the harness redirects into the same in-memory table so tests can read the queue and the miss log the addon wrote. The tests run audio mode first and switch to helper mode with `command('mode', 'helper')` for the queue tests. The C module has no unit tests; `make native-test` is its check.

## Architecture

- **`Spoken.lua`** owns the event handlers and settings. `incoming text` filters by chat mode (150 NPC dialogue with prompt, 144 promptless NPC text, 151 system narration when enabled), runs the line through `text.clean` and `text.player_token`, and hands it to `speak`. In audio mode (`settings.Mode`, the default) `speak` looks the speaker and text up in the pack index and calls the native player; a miss stops whatever was playing, stays silent, and is logged to `data/misses.jsonl` when `settings.Log` or debug is on (reason, raw bytes escaped, zone, position, target, nearest pack lines). In helper mode it appends a queue entry. `incoming chunk` stops on NPC release (`0x52`) and zoning (`0x0B`). `prerender` polls the player's `state()` (or the helper's status file) every `PollFrames` frames and, when auto-advance is on and the current prompted line is `done`, sends Enter through Windower's `setkey`. `unload` shuts the player down.
- **`packs.lua`** is pure: a strict JSON decoder (`packs.decode`; Windower's `json.lua` mis-parses escaped quotes) and the pack index. `packs.load(root, fs)` reads every `audio/<pack>/<version>/manifest.json` through an injected file-system table (`windower.get_dir`, `dir_exists`, `file_exists`, a reader), skips `.part` directories, keeps the highest version per pack, and indexes by speaker plus text, by text, and by a folded letters-only key for diagnosis. `lookup`, `diagnose`, and `describe` are what the addon uses. Paths it returns use backslashes.
- **`native/`** is the player, `libs/spokenplay.dll` (committed, like Balloon's gamepad DLL, because players do not build). `spokenplay_core.c` has no Lua: one worker thread, a mailbox, a generation counter; it reads the Opus file into memory, decodes with opusfile in 100 ms pieces into four winmm waveOut buffers (48 kHz stereo 16-bit, software gain), and only writes `done` or `error` when its generation is still current. `spokenplay_lua.c` binds `play`, `stop`, `state`, `set_volume`, `version`, `shutdown` for Lua 5.1 and leaves a sentinel userdata whose `__gc` shuts the thread down before Lua frees the DLL. `spokenplay_test.c` is the console driver `make native-test` runs under the game's Wine prefix. `build-deps.sh` cross-builds libogg, libopus, and opusfile static from pinned xiph tarballs into `native/deps/` (gitignored). Toolchain: linuxbrew's `i686-w64-mingw32-gcc`, Lua headers from luajit-2.1, linked against Windower's `LuaCore.dll`. The Windows `SP_ERROR` macro is why the states are `SPS_*`.
- **`text.lua`** is pure: `text.clean(raw)` returns `speaker, line, prompted`; `text.player_token(speaker, line, name)` then swaps the player's own name for `<player>`, the form pack keys use. It strips prompt and auto-prompt bytes, colour codes, line breaks, and turns FFXI's private glyph codes (element symbols, music notes, stars) into words or nothing. It mirrors the substitution order in Balloon: raw Shift-JIS byte substitutions first, then `windower.from_shift_jis`, then Unicode-level cleanup.
- **`defaults.lua`** holds user settings; Windower persists them to `data/settings.xml` (gitignored).
- **`helper/spoken_helper.py`** is the host side. The helper itself is stdlib only; the neural backends import from the Python 3.12 venv that `make venv` builds (`uv`, `kokoro-onnx`, `piper-tts`), because onnxruntime has no wheel for the system Python. It tails `data/queue.jsonl`, synthesises each line through a backend (`kokoro`, `piper`, `espeak`, or `none` for dry runs; `auto` tries them in that order), caches WAVs by a hash of speaker, text, and voice, plays them with `paplay`/`ffplay`/`aplay`, kills playback on a stop entry or a newer line, and writes `data/status.json`. Models live in `helper/voices/<backend>/` (gitignored, fetched by `make voices`). Casting: `helper/voices.json` (generated by `helper/cast.py` from a hand-kept list grouped by race, sex, and age band, each group spread round-robin over its pool; never edit the JSON) names the main cast, and every speaker with twenty lines or more has a design of their own in `helper/voice_designs.yaml`; everyone else falls back to `helper/census.json` (generated by `helper/census.py` from a LandSandBoat checkout plus the client's NPC list DATs, with the Rhapsodies speaker list and `--report` audit taken from `tools/xievent.py`; needs the system python3 for PyYAML) through the race-to-pool rules in `helper/casting.py`. `helper/cast_as.yaml` (rules in `helper/cast_as.py`) names who really says a line whose shown name is blank, `???`, or a placeholder, keyed by zone and entity id, because every zone keeps a `???` actor that speaks for whoever is off screen; the pack builder gives such a line that character's voice while its key keeps the shown name, warns about unused entries and unknown names, and stops if one line is cast two ways. Stage directions in a line (`<Sigh>`) are dropped by `strip_directions` before synthesis in the helper, `make say`, the pack builder (a direction-only line is skipped), and the noun counter, but stay in the line's key. `helper/lexicon.yaml` is the pronunciation lexicon (YAML because it is hand-edited; generated files stay JSON), applied before the cache key; an entry's optional `backends:` list limits it to those engines (interjections are kept from moss and qwen, which say them right unaided), and every loader passes its backend's name to `Lexicon.load`. The venv carries PyYAML for it. `helper/review.py` builds and edits it (`make review-lexicon`): a `Session` holds the state, `review_gui.py` is the Tk window over it (a table of every word, incoming and in the lexicon, filtered by status, storyline, and speaker from `data/word_stories.json`, which `tools/voice_stories.py` writes) (the venv's Python has Tk, the system one may not, so tkinter is imported lazily and the tests never need it), and the terminal loop is the fallback.
- **The moss backend** (`helper/moss.py`, `MossBackend` in `spoken_helper.py`) is the pack engine: MOSS-TTS-Local continues a reference clip per voice, with the lexicon's IPA as `/.../` spans minus stress marks (with them it mispronounces). The clips come from `helper/voice_designs.yaml` (hand-edited or through `make review-voices`: per named character gender, age, race, accent, persona, emotion, a description, and a seed; a pool per casting group whose voices carry an age and a description only, since with ElevenLabs the pools are to be stock voices) through Qwen3 VoiceDesign, which is given `designs.compose`'s prompt, the three lines ElevenLabs asks for: "Native <accent>. <Gender>, <age>. <Quality> quality.", "Persona: <persona>. Emotion: <emotion>.", then the description. Race is never in the prompt (there is no `races` section of phrases any more); it is kept on a design for whoever is designing, and must be one of `designs.RACES`. The quality level is not in the file: `QUALITY=` on the Makefile (high by default) reaches every tool that composes as `--quality`, and `make voice-prompts [ONLY=Name]` prints the prompts to paste into ElevenLabs (`tools/design_voices.py`, `make design-voices`, `make listen-voices`; `make audit-voices` says what a run would do and why; in the review window a voice with a take or a clip can be heard saying one of its speaker's own lines from `helper/voice_stories.json` through MOSS, via `helper/moss_say.py` under `.venv-moss`, the window letting go of Qwen first since the two do not fit on the card together) into the gitignored `helper/voices/moss/refs/`; `cast.py` writes a `moss` section into `voices.json` from it. Model and codec do not fit an 8 GB card together, so pack builds run two passes (codes with only the model, then audio with only the codec); `make say` keeps the codec on the CPU. Settings come from `MOSS_*` environment variables and go into the cache key and the manifest. It needs `.venv-moss` (`make venv-moss`: torch 2.9.1, transformers 5, from a MOSS-TTS checkout at `~/scm/github/OpenMOSS/MOSS-TTS`); Qwen needs `.venv-qwen` (`make venv-qwen`, torch and torchaudio pinned together); the Makefile picks `.venv-moss` for `BACKEND=moss`. The system FFmpeg 9 breaks torchcodec, so WAVs are read with `wave`, never `torchaudio.load`. `docs/MOSS-Backend-Handoff.md` records why and the build order; `tools/spike_qwen3.py` and `tools/spike_moss.py` are the listening spikes that chose it.
- **`tools/xidat.py`** reads the client's DATs on the host (dialogue tables, entity lists, event bytecode) using `tools/zone_dats.json`, the per-zone file table from atom0s/XiEvents. **`tools/xievent.py`** disassembles event bytecode (`tools/opcodes.json` from the XiEvents pages) and attributes each line to its speaker; **`tools/ffxitext.py`** is `text.clean` in Python plus the DAT parameter codes, and its tests mirror the Lua ones, so a change to one side is a change to both. `tools/rov_events.py` lists the cutscenes Rhapsodies of Vana'diel runs, from LandSandBoat's mission scripts. **`tools/build_pack.py`** (`make pack VERSION=x`) renders a storyline's corpus into an audio pack under `audio/` (gitignored): one Opus file per unique speaker and cleaned text through the helper's backend and WAV cache, plus the manifest `docs/Audio-Packs.md` specifies, the zip for a GitHub Release (`make release`), and the committed record under `packs/`: a copy of each version's manifest and `index.json` naming the current version, URL, and sha256 of each pack. Audio is never committed and never put in LFS. `docs/Event-Decoding-Handoff.md` is the plan that uses both to attribute every dialogue line to its speaker. **`tools/corpus.py`** (`make corpus`, `make audit-corpus`) extracts what a source says, a source being a mission folder, a quest region of LandSandBoat's `scripts/quests`, or a companion from `helper/companions.yaml` (the Mog House moogle, the Mog Garden), and gives each line one class: dialogue and narration are voiced, unattributed blocks its pack, and system, boilerplate (both from the hand-kept rules in `helper/exclude.yaml`), menu, and unvoiceable never are. The lines go to `data/corpus/` and are never committed, because they are the game's text; `helper/corpus/` holds the counts per source and is. `build_pack.py` (`make pack SOURCE="quests/jeuno ..."`, a mission folder by default) and `voice_stories.py` read this extraction: a pack stops on unattributed dialogue, and `helper/voice_stories.json` counts the unique lines a pack would voice per speaker and storyline (missions, `q-` quest regions, the two companions), with the sample lines the voice review hears kept in `data/voice_lines.json`, out of the repo. `docs/ElevenLabs-Handoff.md` is the plan this belongs to: ElevenLabs for voices and synthesis, nothing of it built yet beyond the extraction. Third-party checkouts are expected at `~/scm/github/LandSandBoat/server` and `~/scm/github/atom0s/XiEvents`.

## Conventions

- Commit and push straight to `master`. Do not create a branch or open a pull request unless asked to.
- `data/` is gitignored and shared with the helper: queue, status, and settings all live there.
- Run the Python tests under both interpreters when touching the helper: `make check` uses the system python3, and `.venv/bin/python -I -m unittest discover -s helper -p 'test_*.py'` covers the venv; for the moss backend, `.venv-moss/bin/python` too. Its tests use a fake engine and never need torch.
- Do not add anything to the addon that blocks the game thread (no synchronous HTTP, no sleeping in handlers). Anything slow belongs in the helper.
- Bump `_addon.version` in `Spoken.lua` and note user-visible changes in `README.md`'s status table while there is no changelog.
- Replacing `libs/spokenplay.dll` while the game has it loaded fails or crashes: `//lua unload spoken` first, `make native`, then `//lua load spoken`. Nothing in `native/` may touch the Lua state from the worker thread or block in a Lua-called function.
- Keep FFXI byte-level knowledge (prompt bytes, element symbols, private Shift-JIS codes) in `text.lua`, with a test for each code, and mirror it in `tools/ffxitext.py` with the same test; the pack lookup key depends on the two cleaning identically.
