# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Spoken is a Windower4 addon for Final Fantasy XI that reads NPC dialogue aloud with generated voices, inspired by the WoW addon of the same name (https://github.com/rusty-key/spoken-wow). It is a work in progress and not usable yet; `README.md` says so and must keep saying so until there is a release.

Direction (2026-11-15): players use pre-rendered audio packs only; a line without downloaded audio is silent. Everything in `helper/` and `tools/` is the developer-side generation pipeline plus the interim player. Playback for players will be a native Lua C module later. `docs/Audio-Packs.md` is the pack design (directories own files; no content-addressed store; lookup by speaker plus cleaned text), `docs/Event-Decoding-Handoff.md` the extraction plan and critical path, `docs/Voice-Handoff.md` the original design record, `docs/Protocol.md` the interim addon-to-helper file contract. Do not propose `windower.play_sound` for playback.

It is a sibling of `../Balloon` (the on-screen dialogue balloon) and shares its scaffolding. Keep the Makefile, `.luacheckrc`, and test harness in step with `../Balloon`, `../ahbuddy`, and `../randommount`.

## Install

Windower runs under the Lumoria flatpak at `~/.var/app/net.windower.Lumoria/data/prefixes/prefix-1/pfx/drive_c/Windower4/`. This repo is symlinked into its `addons/` folder so edits are live after a reload:

```
make install        # find Windower and symlink this repo
make where          # print the folder it would use
```

In game: `//lua load spoken` the first time, `//lua reload spoken` after editing.

## Lint and tests

```
make check                     # luacheck, the Lua tests, and the Python tests
luajit test/test_Spoken.lua    # Lua tests alone; Windower is stubbed
python3 -I -m unittest discover -s helper -p 'test_*.py'
python3 -I -m unittest discover -s tools -p 'test_*.py'
```

Windower's Lua accepts `"fmt":format(x)`; luacheck and luajit do not, so write `("fmt"):format(x)`. `.luacheckrc` whitelists the luau globals; add to it rather than using inline `-- luacheck:` comments.

The Lua harness stubs `luau`, `config`, `chat.chars`, and `windower`, then `dofile`s `Spoken.lua` and drives the `incoming text`, `incoming chunk`, `addon command`, and `prerender` handlers. File writes go through `io`, which the harness redirects into an in-memory table so tests can read the queue the addon wrote.

## Architecture

- **`Spoken.lua`** owns the event handlers and settings. `incoming text` filters by chat mode (150 NPC dialogue with prompt, 144 promptless NPC text, 151 system narration when enabled), runs the line through `text.clean`, and appends a queue entry. `incoming chunk` writes a stop entry on NPC release (`0x52`) and zoning (`0x0B`). `prerender` polls the helper's status file a few times a second and, when auto-advance is on and the helper reports the current prompted line finished, sends Enter through Windower's `setkey`.
- **`text.lua`** is pure: `text.clean(raw)` returns `speaker, line, prompted`. It strips prompt and auto-prompt bytes, colour codes, line breaks, and turns FFXI's private glyph codes (element symbols, music notes, stars) into words or nothing. It mirrors the substitution order in Balloon: raw Shift-JIS byte substitutions first, then `windower.from_shift_jis`, then Unicode-level cleanup.
- **`defaults.lua`** holds user settings; Windower persists them to `data/settings.xml` (gitignored).
- **`helper/spoken_helper.py`** is the host side. The helper itself is stdlib only; the neural backends import from the Python 3.12 venv that `make venv` builds (`uv`, `kokoro-onnx`, `piper-tts`), because onnxruntime has no wheel for the system Python. It tails `data/queue.jsonl`, synthesises each line through a backend (`kokoro`, `piper`, `espeak`, or `none` for dry runs; `auto` tries them in that order), caches WAVs by a hash of speaker, text, and voice, plays them with `paplay`/`ffplay`/`aplay`, kills playback on a stop entry or a newer line, and writes `data/status.json`. Models live in `helper/voices/<backend>/` (gitignored, fetched by `make voices`). Casting: `helper/voices.json` (generated by `helper/cast.py` from a hand-kept race/sex list; never edit the JSON) names the main cast; everyone else falls back to `helper/census.json` (generated by `helper/census.py` from a LandSandBoat checkout plus the client's NPC list DATs, with the Rhapsodies speaker list and `--report` audit taken from `tools/xievent.py`; needs the system python3 for PyYAML) through the race-to-pool rules in `helper/casting.py`. `helper/lexicon.yaml` is the pronunciation lexicon (YAML because it is hand-edited; generated files stay JSON), applied before the cache key. The venv carries PyYAML for it. `helper/review.py` builds it word by word (`make review`): a `Session` holds the state, `review_gui.py` is the Tk window over it (the venv's Python has Tk, the system one may not, so tkinter is imported lazily and the tests never need it), and the terminal loop is the fallback.
- **`tools/xidat.py`** reads the client's DATs on the host (dialogue tables, entity lists, event bytecode) using `tools/zone_dats.json`, the per-zone file table from atom0s/XiEvents. **`tools/xievent.py`** disassembles event bytecode (`tools/opcodes.json` from the XiEvents pages) and attributes each line to its speaker; **`tools/ffxitext.py`** is `text.clean` in Python plus the DAT parameter codes, and its tests mirror the Lua ones, so a change to one side is a change to both. `tools/rov_events.py` lists the cutscenes Rhapsodies of Vana'diel runs, from LandSandBoat's mission scripts. `docs/Event-Decoding-Handoff.md` is the plan that uses both to attribute every dialogue line to its speaker. Third-party checkouts are expected at `~/scm/github/LandSandBoat/server` and `~/scm/github/atom0s/XiEvents`.

## Conventions

- `data/` is gitignored and shared with the helper: queue, status, and settings all live there.
- Run the Python tests under both interpreters when touching the helper: `make check` uses the system python3, and `.venv/bin/python -I -m unittest discover -s helper -p 'test_*.py'` covers the venv.
- Do not add anything to the addon that blocks the game thread (no synchronous HTTP, no sleeping in handlers). Anything slow belongs in the helper.
- Bump `_addon.version` in `Spoken.lua` and note user-visible changes in `README.md`'s status table while there is no changelog.
- Keep FFXI byte-level knowledge (prompt bytes, element symbols, private Shift-JIS codes) in `text.lua`, with a test for each code, and mirror it in `tools/ffxitext.py` with the same test; the pack lookup key depends on the two cleaning identically.
